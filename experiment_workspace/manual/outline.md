## 一、目标读者

| 维度 | 描述 |
|---|---|
| **核心读者** | 非技术背景的中小企业主 / 个体创业者——希望用 AI 团队替代或扩展人力，但不会写代码、不熟悉命令行 |
| **次要读者** | 业务经理、项目经理——负责定义需求、验收交付物、管理审批流程 |
| **排除读者** | AgentOS 开发者/贡献者（他们看 CONTRIBUTING.md 与源码） |
| **读者假设** | ① 会使用浏览器和基础办公软件；② 知道"AI 大模型"概念但不了解技术细节；③ 可能需要他人协助完成首次安装部署 |

**核心原则：让读者像经营一家真实公司一样理解 AgentOS——用"公司、员工、部门、派单、审批"等日常商业概念，而非"Agent、DAG、LiteLLM"等技术术语。**

## 二、章节结构

### 第 1 章　认识 AgentOS

> 一句话定位：AgentOS 是你的 AI 数字公司操作系统——你当老板，AI 员工干活，你签收成果。

| 小节 | 要点 |
|---|---|
| 1.1 AgentOS 是什么 | · 不是聊天工具，是"AI 公司"操作系统 · 每个 AI 员工有独立身份、岗位、能力、权限和记忆 · 员工之间真实协作并互相验证 · 你始终拥有最终签收权 |
| 1.2 它能帮我做什么 | · 自动完成市场调研、产品设计、文案撰写、前端开发、测试等全流程 · 典型场景：建企业官网、开发网页应用、生成调研报告 · 用真实案例说明（星舟科技官网交付、贪吃蛇游戏交付） |
| 1.3 与普通 AI 聊天工具的区别 | · 对比表：聊天工具 vs AgentOS（单轮对话 vs 多员工流水线、无审批 vs 双关卡审批、无权限 vs 五层权限、无记忆 vs 三级记忆） |
| 1.4 运行方式与安全承诺 | · 本地优先：默认只监听 127.0.0.1，数据不出本机 · Shell 永久禁用，无命令执行路径 · 密钥只存环境变量引用，不入数据库 · 全量审计留痕 |

### 第 2 章　快速开始

> 目标：30 分钟内从零到看到第一个任务执行结果。

| 小节 | 要点 |
|---|---|
| 2.1 系统要求 | · 操作系统（Windows / macOS / Linux）· Python 3.13 + Node.js · 磁盘与内存建议 |
| 2.2 安装步骤 | · 后端：创建虚拟环境 → 安装依赖 → 初始化数据库 → 启动 API 服务 · 前端：安装依赖 → 启动开发服务器 · 用编号步骤 + 每步预期输出呈现 |
| 2.3 零成本体验（Mock 模式） | · 不填任何 API Key 即可完整运行 · Mock 模式说明：不调用外部服务，不计费 · 适合：熟悉界面、理解流程、培训员工 |
| 2.4 接入真实 AI 模型 | · 获取 API Key（以 DeepSeek 为例）· 填入 .env 文件 · 切换执行模式为 real · 费用预估与控制提示 |
| 2.5 第一个任务：让 AI 员工写一份市场调研 | · 建公司 → 建 AI 员工 → 绑模型 → 创建任务 → 查看执行 → 审批签收 · 全程截图指引（占位标注，待实际截图替换） |

### 第 3 章　建 AI 公司

> 核心隐喻：你是在"注册一家公司"——有名称、部门、岗位、员工。

| 小节 | 要点 |
|---|---|
| 3.1 创建公司 | · 公司名称与简介 · 一台电脑可管理多家公司（多公司支持） |
| 3.2 搭建组织架构 | · 创建部门（如：产品部、设计部、开发部、测试部）· 定义岗位（岗位名称 + 职责描述）· 设置上下级关系 · 可视化组织图（点击展开员工详情） |
| 3.3 招聘 AI 员工 | · 员工四要素：名称、头像、岗位、简介 · 性格与行为规则（如："注重细节""先调研再动手"）· 系统提示词（用自然语言描述，非代码） |
| 3.4 为员工分配能力 | · 工具授权：决定员工可以使用哪些工具（文件读写、HTTP 请求、图片识别等）· 工作权限：最小权限默认，按需开放 · 工作区授权：员工只能访问被授权的项目目录 |
| 3.5 为员工绑定 AI 模型 | · 员工与模型解耦：同一模型可服务多个员工，一个员工可配主备模型 · 主备模型故障自动切换 · 已验证模型列表（DeepSeek、智谱 GLM-4V/4.6V、OpenRouter）· 连接测试方法 |
| 3.6 组织配置导入导出 | · 将整套组织架构导出为配置文件 · 从配置文件快速重建公司 · 场景：备份、迁移、分享团队模板 |

### 第 4 章　任务与审批

> 核心隐喻：你是"老板派活 + 签收验收"——AI 员工执行，你把关质量。

| 小节 | 要点 |
|---|---|
| 4.1 创建任务 | · 任务标题与描述（用自然语言，像给人类员工下指令）· 指定负责员工 · 设置优先级与截止时间 |
| 4.2 任务生命周期 | · 状态流转图：待分配 → 执行中 → 待审批 → 已签收 / 已退回 · 失败自动重规划 · 断点续跑：中断后从检查点恢复 |
| 4.3 子任务与依赖 | · 大任务拆解为子任务 · 设置依赖关系（如：设计完成后才能开发）· 并行执行无依赖的子任务 |
| 4.4 智能派单 | · 系统根据岗位匹配度、历史表现自动推荐候选人 · 候选人评分展示 · 一键创建任务并分配 |
| 4.5 审批中心 | · 执行前审批：高风险操作开始前需你批准 · 交付后审批：员工提交成果后需你签收 · 审批卡片内嵌成果预览（如：网站实际渲染效果）· 看着成果批，而不是读文档猜 |
| 4.6 退回与返工 | · 审批不通过时退回任务 · 员工根据退回意见修改 · 返工上限防止无限循环 |
| 4.7 任务执行控制 | · 暂停 / 恢复 / 取消正在执行的任务 · 人工接管：必要时自己接手 |

### 第 5 章　工具与安全

> 核心隐喻：你给员工"工位和工具箱"——规定能用什么、能访问什么。

| 小节 | 要点 |
|---|---|
| 5.1 工具总览 | · 文件读写工具 · HTTP 请求工具 · 图片识别工具（AI 看图提取设计规范）· 工具全局开关（默认关闭，按需开启） |
| 5.2 五层权限体系 | · 用"公司门禁"类比逐层收窄：① 全局开关（公司大门）→ ② 公司策略（部门权限）→ ③ 员工白名单（工位钥匙）→ ④ 岗位权限画像（岗位资格）→ ⑤ 工作区读写授权（文件柜钥匙）· 缺一不可，最严层生效 |
| 5.3 工作区与文件安全 | · 工作区：项目级隔离空间，员工只能访问被授权的目录 · 路径安全：拒绝绝对路径、盘符、.. 逃逸、符号链接 · 敏感文件防护：.env / 密钥 / ssh 文件直接拒绝访问 |
| 5.4 网络请求安全 | · HTTP 域名白名单 · DNS 逐 IP 校验（防 SSRF 攻击）· 重定向逐跳检查 |
| 5.5 审计与熔断 | · 全量操作审计留痕（脱敏处理）· 预算熔断：超出预算自动停止任务 · 连续拒绝熔断：多次被拒后暂停 · 全局紧急开关（Kill Switch） |
| 5.6 高危操作审批清单 | · 9 类高危操作分类说明 · 每类操作的审批流程 · Agent 不可自批（红线规则） |

### 第 6 章　记忆

> 核心隐喻：员工有"笔记本"——记住公司规范、项目经验、个人心得。

| 小节 | 要点 |
|---|---|
| 6.1 三级记忆作用域 | · 员工私有记忆：只有该员工自己能读（如：个人工作习惯）· 项目记忆：项目组内共享（如：项目技术栈、设计规范）· 公司记忆：全公司共享（如：品牌规范、公司制度） |
| 6.2 记忆如何工作 | · 执行时自动检索相关记忆注入上下文 · 中文 2-gram 全文检索（FTS5）· 记忆条目的增删改查 |
| 6.3 记忆最佳实践 | · 什么该记、什么不该记 · 保持记忆精简避免上下文膨胀 · 定期清理过时记忆 |

### 第 7 章　监督与质量

## 三、写作规范

### 3.1 语言与语气

| 规范 | 说明 |
|---|---|
| **语言** | 简体中文，全站统一 |
| **语气** | 专业但亲切，像一位有经验的顾问在指导——避免说教感，避免过度口语化 |
| **人称** | 用"你"称呼读者（而非"用户"），用"AI 员工"或"员工"称呼 Agent（而非"智能体""Agent"） |
| **术语** | 首次出现技术术语时必须附通俗解释（如："Token（即 AI 处理文字的计费单位）"）；术语表统一收录于附录 A |
| **禁用** | 禁止使用"简单""只需""轻松"等暗示操作无难度的词——对非技术读者，每步都可能不简单 |

### 3.2 结构与格式

| 规范 | 说明 |
|---|---|
| **章节深度** | 最多三级标题（章 → 节 → 要点），避免过深嵌套 |
| **步骤说明** | 用编号列表（①②③），每步包含：操作 → 预期结果 → （可选）出错怎么办 |
| **示例格式** | 每个功能点至少配一个具体示例，格式为"场景 → 操作 → 结果"，示例用引用块 `>` 标识 |
| **截图/图示** | 所有 UI 操作配截图占位（标注 `[截图：XXX]`，待实际截图替换）；流程配 Mermaid 图 |
| **对比说明** | 用表格呈现对比信息（如：Mock vs Real 模式、聊天工具 vs AgentOS） |
| **警告提示** | 安全相关用 `> ⚠️` 标识；费用相关用 `> 💰` 标识；重要提示用 `> 📌` 标识 |

### 3.3 内容红线

| 红线 | 说明 |
|---|---|
| **禁止编造功能** | 只写 FEATURE_MATRIX.md 中已标注 ✅ 或 🧪 的功能；🔵 设计中 / ⬜ 未开始的功能仅在附录 D 路线图中提及，并明确标注"规划中，尚未实现" |
| **禁止虚构截图** | 截图占位必须标注 `[截图：描述]`，不得用文字描述冒充截图 |
| **禁止承诺未验证的性能** | 不写"秒级响应""零延迟"等未实测的性能声明 |
| **安全信息必须准确** | 五层权限、Shell 禁用、路径安全等安全描述必须与 README.md 架构章节一致，不得简化或模糊化 |
| **费用信息必须诚实** | 明确区分 Mock 模式（不计费）与 Real 模式（真实计费）；提供费用控制方法而非回避费用话题 |

### 3.4 文件组织

| 规范 | 说明 |
|---|---|
| **文件命名** | `docs/manual/ch01-认识AgentOS.md`、`ch02-快速开始.md`……`ch10-FAQ.md`、`appendix-A-术语表.md`…… |
| **图片目录** | `docs/manual/assets/`，图片命名 `ch01-org-chart.png` |
| **索引文件** | `docs/manual/README.md` 为手册首页，含目录链接与版本信息 |
| **交叉引用** | 章节间用相对链接引用，不硬编码外部 URL |
