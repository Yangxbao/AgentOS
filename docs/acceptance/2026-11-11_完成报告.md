## 2. 实现与验证

### 2.1 config_io 导入安全加固 ✅（标准提高）
被篡改的配置包现在无法注入脏数据：
- 工作区 `mode/status` 非法值 → 回退默认（read_write/active）
- 记忆 `scope/kind` 非法值 → 回退默认（employee/note）；`content` **导入时再脱敏一次**（防御纵深：导出时已脱敏，包传输中仍可能被篡改）；`title` 同样脱敏
- employee 作用域记忆的原员工不在导入中 → 跳过并记 warning（不产生无主记忆）
- 计数修正为实际导入数（跳过项不计）

**测试**：`test_import_hardens_tampered_values`——构造篡改包（非法 scope/kind/mode/status + 含 `sk-tamperedkey12345678` 的记忆），断言：非法值回退默认、密钥再脱敏（`sk-***`）、越权记忆跳过、非法 root 跳过记 warning。另补 `test_dry_run_tolerates_m3_bundle_files`（dry_run 对含 M3 新文件的包正常预检）。`tests/test_config_io.py` 9/9。

### 2.2 创建表单：审批阶段 + 审核人 ✅
勾选"需要人工审批"后出现：**审批阶段下拉**（执行前/交付前）+ **审核人下拉**（本地用户默认；可选员工，后端校验 can_review 与"≠执行人"，选错会显示真实 422 原因）。payload 增 `approval_stage/reviewer_employee_id`（后端字段既有）。

### 2.3 任务详情执行模式标识 ✅
头部新增模式徽标（**真实模型** 紫色高亮 / Mock / 自动）+ 预算徽标（`$X.XX`）——实验时一眼确认任务确实以 real 模式执行、预算多少。

### 2.4 浏览器验收 B7 竞态修复 ✅
B7（多 Agent 协作断言）间歇失败：`wait_text("已完成")` 成功后，时间线的 `agent.handoff` 事件可能尚未被前端轮询拉取，断言立即执行就撞空。修复：断言改为**轮询重试**（20 次 × 0.5s，对齐 B5.5 模式）。**连续两次运行 32/32** 稳定。这是验收脚本健壮性问题，非产品缺陷。

2. 审核人下拉**未做 can_review 前端过滤**（列出全部员工，文案说明资格要求）——选错由后端 422 真实拒绝并显示原因；如需前端过滤需逐员工查 capabilities（开销不匹配本地单用户场景）。
3. B7 竞态的根因定位是现象级的（前端轮询与断言时序），未深挖 TanStack Query 的失效刷新链——轮询重试是工程正解。
4. 嵌套审批/自动续跑/预算预扣/重规划 UI 等前几轮功能本轮回归全过，无退化。
