## 2. 功能一：预算预扣（真实资金保护强化）✅

**实现**：`budget.estimate_call_cost(model, mode)` —— 仅 **real 模式**生效（mock 从不计费，预估恒为 0，Mock 全链路零影响），按模型目录档位（与既有静态预估同源）把**下一次调用的保守成本**计入步骤入口的预算检查。real 下未知模型按 middle 档（$0.03）保守估计。
**效果**：成本超支在**调模型之前**被拦截并暂停任务（`BUDGET_EXCEEDED`），而不是"先花钱、下一个检查点才补救"。单次超支上限从"无界"降为"0 次"。
**验证**：单元级（deepseek real=0.01 / mock=0 / 未知=0.03）；既有预算测试全过（mock 路径行为零变化）。

## 3. 功能二：三层级联自动续跑 ✅

**实现**：自动续跑 hook 条件从 `trigger=approval` 扩展到 `approval/auto_resume` 两类独立子 run——子任务成功收尾后逐层向上恢复（孙→子→父→祖父），事件 `task.auto_resumed` 逐层落时间线。
**过程中发现并修复一个真 bug**：`enqueue_run` 的子任务豁免清单只有 `approval`，`auto_resume` 入队会 409"子任务不能单独运行"——调试日志定位后补全豁免。
**测试**：新增三层嵌套（祖父→父→子）审批批准后级联续跑用例：祖父 succeeded、父/子均 succeeded、父/祖父时间线各有 `task.auto_resumed`、工作区产物真实落盘。`test_m3b_recursion.py` 11/11。

## 4. 功能三：任务重规划 UI ✅

任务详情页对 `failed / rework_required` 状态显示**重规划区块**：每步 instruction 可编辑、标记失败步骤（radio）、显示 `已用 N/3 次 · 计划版本`、提交后提示"请点重试重新入队"（replan 只改计划与检查点，重试才执行——与后端语义一致）。走既有 `POST /tasks/{id}/replan`（≤3 次、上游产出保留、审计留痕）。

## 8. 诚实声明

1. 开发中犯了一个低级错误并当场修复：把 `primary_model_id` 当成 Task 字段（实为 Employee 字段），嵌套入口的预扣因此多余且报错——已删除冗余调用（预扣由每层子步骤的单步入口覆盖，语义更准确）。
