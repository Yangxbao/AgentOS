## 1. 原始验收条款（审核基准）

任务下达时依据两份文档，条款原文如下：

**A. HANDOFF.md §12（任务清单，5 条）**

1. 预算：新增 `packages/execution/budget.py`——读 `task.budget_usd` + 公司策略默认预算；按 `usage_record` 累计 cost 与 tokens；超限：`task.state=paused` + `TaskEvent("task.budget_exceeded")` + `task.result.error`；在 `executor._run_step` 调模型前检查，`tool_loop` 每次工具调用后也检查
2. 连续拒绝/失败：`task_run.checkpoint` 里累计 `denied_count`，≥3 → 暂停并提示"检查授权"
3. 全局 kill switch：`POST /api/v1/system/tool-execution`（仅本地用户）→ 写公司策略或进程级开关，审计留痕
4. 监控：`/monitor` 增加工具调用统计、拒绝原因 Top N、预算使用率
5. 验收场景：单步 8 次工具 → 终止；超预算 → paused；连续 3 次拒绝 → paused；`AGENTOS_TOOL_EXECUTION=off` → 所有调用拒绝且任务可读地失败

**B. M3_MASTER_PLAN.md §13 M3-E（验收，5 条）**

1. 单步骤工具调用 8 次后终止；
2. Token/费用超预算 → 任务 `paused` + 原因，不继续调用；
3. 连续 3 次 `TOOL_DENIED` → 暂停并提示检查授权；
4. 工具输出异常（超大/非法编码）被拦截且记录；
5. 全局 `AGENTOS_TOOL_EXECUTION=off` 时所有工具调用拒绝且任务可读地失败。

## 5. 设计决策与取舍（审核重点）

| 决策 | 选择 | 理由 | 替代方案（未采纳） |
|---|---|---|---|
| 超预算/连续拒绝的终态 | **暂停（paused）不是失败** | 保留检查点与已完成步骤，人工处理后从断点续跑；与静态预估超支（`EXECUTION_BUDGET_EXCEEDED` 入队前直接拒绝，M2 既有）形成两层语义 | 直接 failed（会丢弃已完成步骤的可续跑性） |
| kill switch 的持久化 | **进程内存态**，重启回到 `AGENTOS_TOOL_EXECUTION` 初始值 | 紧急制动要求"立即生效 + 审计留痕"；持久关闭属于配置，应走环境变量。已在 API 文档、HANDOFF、UI 文案三处明示该限制 | 写库/写 env（写 env 需要改系统配置，违反项目红线） |
| Token 限额来源 | 仅公司策略 `policy.default_task_budget_tokens`（无任务级 Token 字段） | 避免新增列/迁移（本任务零迁移）；成本已有任务级字段 | 加 `task.budget_tokens` 列（需要迁移，收益低） |
| `denied_count` 语义 | run 级、跨步骤/跨 run 经 checkpoint 继承；**任何非拒绝终态（成功/失败/超时）归零**；审批挂起不计入 | "连续"的字面语义；失败/超时是执行问题而非授权问题，混入会让熔断过早触发 | 按错误码细分计数（复杂度高，验收条款未要求） |
| 预算检查的 pending 消耗 | 工具循环内每轮模型响应后，把**尚未落库**的本轮消耗并入检查 | usage_record 在步骤结束才落库；若只查 DB，单步内连调多次模型的成本会在步骤结束前持续漏计 | 只查 DB（会漏计，预算形同虚设） |
| 全局 off + 无必需工具 | 保持 M2 语义：跳过工具、单次调用完成任务 | 既有行为，M2/M3-A 大量测试依赖；仅当步骤**声明**必需工具时才可读失败 | 一律失败（破坏既有契约，超出本任务范围） |

## 6. 顺带修复的既有 bug（M3-A 遗留）

**审批恢复后 `tool_state` 残留**：恢复执行时 `tool_state` 只从内存快照 `pop`，从未写回 DB；步骤收尾的 checkpoint 合并以 DB 为准，导致挂起状态永久残留。后果：同一步骤在返工/重试再次进入工具循环时会被误判为"仍在等审批"，且待执行调用的状态已非 `approved`，直接抛 `TOOL_APPROVAL_REJECTED`。修复：恢复路径执行完待批准调用后，以 DB 为准读-改-写清除 `tool_state`（`_persist_checkpoint`）。未发现既有测试因此变红（该路径此前无覆盖），已在 CHANGELOG 的 Fixed 节记录。

## 7. 诚实声明（未解决/未覆盖，审核者请勿采信超出以下范围的结论）

1. **真实模型链路未验证**：全程 Mock。LiteLLM 的真实 tool_calls 解析、真实计价下的预算熔断，只有 M2 时代的 4 次真实调用记录（$0.00006285），M3-A/M3-E 均 0 次。
2. **kill switch 重启失效**：进程内存态，重启后回到 env 初始值（明示过的取舍，非遗漏）。
3. **`denied_count` 跨并行步骤的竞态**：多步骤并行时各自 session 读-改-写同一 run.checkpoint，极端并发下计数可能少计（与既有 `tool_calls_count` 累计同级别的一致性模型，SQLite 单写者下为 last-write-wins；验收场景为单步骤，未受影响）。
4. **预算不拦"进行中"的单次超支**：检查在模型响应**之后**，一次调用的成本先发生、后核算；单次调用本身没有上限（`AGENTOS_MAX_TOKENS` 仅限输出长度）。
5. Windows TOCTOU、本地恶意进程直连 SQLite、提示词注入等 M3-A 既有边界**原样存在**，本任务未扩大也未收窄（见 HANDOFF §8.2）。
6. 代码**未提交**（git 工作区 16 文件变更），等审核结论后一并处理。
