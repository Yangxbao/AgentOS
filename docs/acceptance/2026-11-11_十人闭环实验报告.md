## 1. 网站补全：工作区文件浏览器 ✅

**缺口**：Agent 产出的文件（报告/文档）落在工作区目录里，但 UI 无法查看——用户要去文件管理器找。

**实现**（后端零依赖复用安全核心）：
- `GET /workspaces/{id}/files?path=` 列目录（`safe_resolve` 防逃逸，上限 500 条）
- `GET /workspaces/{id}/files/content?path=` 读文本（同工具层标准：256KB 上限、二进制拒绝、**密钥扫描**）
- 语义：**owner 管理视图**——工作区本就是 owner 资源，本地用户浏览不需要员工授权（与 Agent 五层权限是两条正交路径，文档已写明）；只读、不产生工具审计（非 Agent 调用）
- 前端：WorkspacesPage 每个工作区卡片内嵌文件浏览器（目录导航/上一级/文本预览/文件大小）

**验证**：+3 测试（列目录与读取/路径逃逸与不存在/二进制 415），`test_config_io.py` 12/12。浏览器验收 32 项全过。

## 3. 真实发现（本实验最有价值的部分）

1. **免费模型 function calling 可靠性差异是真实的**：
   - 智谱 GLM-4-Flash：**3/3 工具调用全部成功**（s1×2 读、s8 写、s10 写——4 次，全成）
   - OpenRouter Nemotron :free：**function calling 时灵时不灵**——s6（开发工程师）未调用 fs.write_file 而是文本输出，导致 implementation_plan.md 未落盘 → 连锁导致 s7 读取失败（1 条 failed 工具调用）
2. **失败链路展现了系统的容错语义**：s7 读取失败 → 失败结果作为数据回灌模型 → 模型调整继续 → 任务仍 succeeded——"拒绝/失败不阻断、回灌自适应"的设计在真实链路得到验证
3. **质量审核员发现了问题**：s9 的审核输出指出"上游输出重复"现象——模型的批判性观察
4. 结论：**真实生产用智谱（免费且 function calling 稳定），Nemotron :free 建议只用于文本类步骤**——这是花钱买不来的一手数据

## 4. 过程事故（已修复，如实报告）

1. **tools.py 写入 NULL 字节**：heredoc 双层转义导致 `b"\x00"` 字面量变成真实 NULL 字节 → 语法错误。用字节算术（`bytes([92]) + b'x00'`）替换修复，文件内容验证正确。
2. **.env 配置行拼接损坏**（2026-11-10）：`.env` 末尾无换行时追加 `ZHIPU_API_KEY`，与用户的 `AGENTOS_TOOL_EXECUTION=on` 拼成一行——两个配置同时失效。已拆行修复并验证。教训：**追加配置文件前必须检查末尾换行**。
