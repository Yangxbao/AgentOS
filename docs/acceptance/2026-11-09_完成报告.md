## 1. 本轮目标

沿用"使用前免费验收"的盘点方法，专找**明天真实实验直接依赖但前端缺失**的功能。发现三处：

| # | 缺口（修复前） | 对明天实验的影响 |
|---|---|---|
| 1 | 任务创建表单**没有执行指令输入框、没有预算输入**（payload 只有 title/objective 等；后端 `TaskCreate.instruction/budget_usd` 字段早已存在） | 明晚实验无法在 UI 设置预算熔断；指令与目标混用体验差 |
| 2 | **审批中心与任务详情审批面板都不显示审批上下文**——批准的人看不到"批准的具体是什么工具调用、什么参数" | 审批人盲批，违背"看得见批准的是什么"的安全可用性原则 |
| 3 | 浏览器验收 29 项**不含审批中心页面的任何断言**（上轮完成报告 §7 如实声明过） | 审批中心页面无回归保护 |

## 2. 实现

**① 任务创建表单补全**（`TasksPage.tsx`）：新增执行指令 textarea（单员工任务的完整指令）与预算 USD 输入（只允许数字，创建即可设熔断上限）；payload 增 `instruction/budget_usd` 两字段（后端 schema 早已支持，零后端改动）。执行模式下拉本就含 real/mock/auto。

**② 审批上下文展示**（新增 `components/approvalText.ts` helper，两处接入）：
- 审批中心列表与任务详情审批面板各加一行 context 摘要：`tool_call` 审批显示"**调用工具 fs.write_file（风险 high）· 参数 {脱敏摘要}**"；交付前审批显示步骤/摘要
- context 来自后端既有序列化（`serialize_approval` 含 context，参数在写入时已脱敏）——零后端改动

**③ 浏览器验收 B5.5**：新增审批中心页断言（聚合显示待审批 + 任务标题 + 闸门标签），验收项 29 → **30**。

## 3. 过程中的排查战（如实记录）

B5.5 首跑失败，页面文本只有 "AgentOS"（导航品牌词）。三轮取证（page DOM dump、同刻双 eval 探测）后定位：**这不是产品缺陷**——React 首次提交与数据加载之间存在"只有 header 的渲染中间态"，单次 CDP eval 会撞上；而既有的 `wait_text` 本身是轮询语义所以其余 29 项从没暴露过。修复：SPA 页面断言改为**单次原子 eval + 轮询重试**（对齐 wait_text 语义）。另有两处脚本小错（JS 双引号嵌套破坏 Python 源码、json 别名替换误伤全文件引用）当场修复——教训：**对脚本做字符串替换后必须先跑语法检查再运行**。

## 6. 诚实声明

1. 本轮**未修任何产品缺陷**——三处都是 UI 补全，后端零改动。
2. B5.5 的"React 中间态撞单次 eval"现象只做了现象级定位（两次 eval 结果不同、原子 eval 稳定复现中间态），未深挖 React 提交时序——工程上轮询重试已是正确解法（与 wait_text 同语义）。
3. 岗位（positions）编辑 UI 仍未做（员工详情页有"到组织设置维护"提示）——PATCH 支持该字段，属低优先级 UX。
4. 明晚实验仍需用户手动执行（费用授权）；所有配置与断言已就绪。
