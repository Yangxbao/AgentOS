## 2. 修复与实现

### 2.1 修复上轮引入的 bug：监控 Worker 面板永远空白 ✅
上轮给监控页加了 Worker 面板（读 `data.workers`），但**后端 `monitor/summary` 没有返回该字段**——面板永远显示"当前没有持有租约的 worker"，且类型标记为 optional 所以 tsc/build/浏览器验收都没拦住。本轮自检抓到后修复：`/monitor/summary` 响应补 `workers`（与 `/workers` 端点同源，`TaskRunner().workers_snapshot()`）+ 回归测试断言该键存在。教训已记录：**前端新增字段时必须同步验证后端聚合是否提供**。

### 2.2 员工详情页记忆区块 ✅
新增"员工记忆"区块：列出该员工的私有记忆（employee 作用域）、快速写入（标题+内容，密钥自动脱敏）、删除。用途：明晚实验可逐员工测试记忆隔离（甲的记忆乙检索不到——已有专项测试）与记忆写入（Agent 走 `memory.remember` 工具的路径不变）。

### 2.3 前端全局 ErrorBoundary ✅
React 子树渲染崩溃时显示可读错误 + 重试按钮，不再白屏（真实实验中某页面异常不会再让用户无从下手）。

### 2.4 审批中心补"要求修改"操作 ✅
三操作（批准/驳回/要求修改）与任务详情审批面板完全对齐。

### 2.5 文档债清偿 ✅
CHANGELOG 补齐 **M3-B/C/D/F 批次 + 员工配置中心 + 嵌套审批自动续跑 + 预算预扣** 的完整条目（此前只记到 M3-E）。

## 5. 诚实声明（含未实现/未验证项）

1. **config_io 导出不含工作区/授权/记忆**（自检如实报告，本轮未实现补齐）：工作区 root_path 是本机路径，跨机器导入价值有限；如需迁移实验环境，当前用备份库方式。标记为已知限制而非缺陷。
2. 员工记忆区块的"写入"是**人工写 owner 视角**的私有记忆（与 Agent 的 memory.remember 同表同作用域）；Agent 写入路径不变。
3. 预扣语义测试是单元级（check 的 pending 算术）；端到端 real 预算拦截仍待用户真实实验验证（mock 预估恒 0，无法在 Mock 下端到端呈现）。
4. 岗位（positions）编辑 UI 仍未做（低优先级 UX，PATCH 字段已支持）。
5. FTS5 中文按连续字串 token 匹配的召回质量未提升（trigram 等方案涉及 SQLite 版本兼容，未启动）。
