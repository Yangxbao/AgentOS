## 1. 本轮目标

延续盘点方法，本轮聚焦**统一实验的操作路径**上最后四个缺口：

| # | 缺口（修复前） | 影响 |
|---|---|---|
| 1 | 任务列表**无搜索框**（后端 q 参数一直支持）；创建任务后停在列表页 | 多任务时找任务低效；创建后要多点一次 |
| 2 | 记忆**没有编辑功能**（client 有 update API，UI 只有增删） | 写错只能删了重写 |
| 3 | 员工详情记忆区块**没有检索预览** | 无法直观验证"这个员工能检索到什么"（记忆隔离的核心卖点） |
| 4 | 任务详情**成本区不显示预算对比**；重规划后要**回顶部找重试按钮** | 预算熔断状态不直观；操作动线割裂 |

## 2. 实现与验证

### 2.1 任务列表搜索 + 创建后跳转 ✅
TasksPage 新增搜索框（标题/目标，走后端既有 `q` 参数）+ 创建任务成功后**自动跳转任务详情**（`navigate`）。

### 2.2 记忆编辑 ✅
MemoryPage 记忆卡片新增"编辑"：内联编辑标题与内容（走既有 `PATCH /memories/{id}`，写入重新脱敏 + FTS 同步），保存/取消，成功后列表刷新。

### 2.3 员工视角检索预览 ✅
员工详情"员工记忆"区块新增**检索预览框**：以该员工视角搜索（走 `/memories/search?employee_id=` 的 viewer 隔离），结果**标注作用域来源（私有/项目/公司）**。用途：直接验证"甲能检索到乙的私有记忆吗"——答案应该是"检索不到"，这是记忆隔离的直观测试工具。

### 2.4 任务详情预算对比 + 重规划内联重试 ✅
成本明细区块：设了预算的任务显示"预算 $X（已用 Y%）"，超支变红；重规划区块提交成功后**内联"重试任务（重新入队）"按钮**，操作动线不再割裂。

## 5. 诚实声明

1. 本轮**后端零改动**——四项全部是前端能力补全（后端 API 早已支持），无新增后端测试（既有 352 项已覆盖对应 API 语义；记忆检索的 viewer 隔离已有专项测试）。
2. 记忆编辑走 `PATCH /memories/{id}`，内容**重新脱敏**——与创建相同的审计与 FTS 同步路径。
3. 任务列表搜索命中后端 `LIKE` 匹配（title/objective），大小写不敏感按 SQLite LIKE 语义；分页固定 page_size=100（本地单用户量级合理）。
4. 检索预览的"员工视角"即 `/memories/search` 的 viewer 过滤——与执行时 `retrieve_for_step` 的隔离逻辑同源，但不等于执行时注入（注入还叠加步骤指令相关性排序）。
