## 2. 修复一：前端创建公司 403（UNTRUSTED_REQUEST cross-site）

**现象**：`http://localhost:5173` 页面点创建公司，`POST /api/v1/companies` 403；后端日志 `UNTRUSTED_REQUEST: 跨站写请求被拒绝 (Sec-Fetch-Site: cross-site)`。
**根因**：前端 `client.ts` 直连 `http://127.0.0.1:8000`，**Vite 根本没有代理配置**（"改 changeOrigin"的建议前提不成立）。浏览器把 `localhost:5173 → 127.0.0.1:8000` 的请求标为 **cross-site**（site 判定与端口无关，localhost 与 127.0.0.1 是不同 site）→ 被 LocalGuard 正确拒绝。`127.0.0.1:5173` 页面因 IP 相同属 same-site，所以自动化浏览器验收一直能过——这正是用户手工测试才发现的原因。
**修复（最小）**：`vite.config.ts` 新增 `/api` 代理（target 127.0.0.1:8000，`changeOrigin: true`——后端 Host 校验只看主机名，true/false 都能过，**与 403 无关**）+ 新增 `.env.development`（`VITE_API_BASE=` 置空 → 同源相对路径，仅 dev 生效，生产构建不变）。
**验证**：经代理创建公司 201、列表/PATCH 正常；恶意 cross-site 直连后端**依旧 403**（防护未削弱）。
提交：`b0ddcef`。

## 4. 修复三：执行监控页"恢复工具执行"POST 200 但状态不变

**排查（未预设结论）**：实测运行进程 `GET /system/tool-execution → {"env_enabled": false, "kill_switch": false, "enabled": false}`——用户的 `.env` 实际**没有** `AGENTOS_TOOL_EXECUTION` 行（与其任务书声明不符）。点「恢复」的 POST `{enabled:true}` 确实执行了，但 kill switch 本来就是 false，有效状态（env ∧ kill）仍是 off → **返回 200 + `{"enabled": false}` 的静默 no-op**。前端 mutation 无 onError、无 Toast，错误完全静默。字段命名/React 缓存/changeOrigin 等嫌疑逐项排查排除。
**修复**：① 后端 env off 时请求开启 → **409 `TOOL_EXECUTION_BLOCKED_BY_ENV`**（含"请在 .env 设置后重启"指引），紧急停止永远可用；② 前端补 onError + 成功/失败 Toast + 返回状态一致性校验。
**验证**：重启后端后实测 POST 恢复 → 409 带指引（不再静默 200）；monitor GET 与开关同源一致；用户随后自行配置 env=on 并重启，**实测 POST 恢复 → 200 + enabled=true**，按钮正常工作。
**新发现的运维语义（如实记录）**：env off 时 kill 一旦打开只能靠重启后端复位（API 409 拒绝清除；功能上无差异——两种状态工具都是关的）。
提交：`2045b5b`。

## 5. 新功能：AI 员工配置中心（本批主体）

**问题**：真实测试时模型提示没有可用工具——员工 `tools_allowed` 白名单为空，而前端员工模块**没有编辑工具授权和工作区授权的任何入口**。

**架构检查结论（先查后做）**：`PATCH /employees/{id}` 已存在且支持 `tools_allowed`（含审计 diff）；工作区 grant/revoke API、跨公司隔离（`WORKSPACE_COMPANY_MISMATCH`）、五层诊断端点 `/employees/{id}/tool-permissions` 全部已有——**全部复用，不重写权限系统**。后端唯一缺口：`tools_allowed` 写库前不校验工具名。

**实现**：
- 后端（唯一改动）：`tools_allowed` 写库前按工具注册中心校验（非法名 422，create+PATCH 两路径）+ 去重规范化
- 前端：员工列表卡片新增"已授权工具 N 项 / 已授权工作区 N 个 / 模型"概览 + 「编辑配置 →」；员工详情页新增三区块——
  ① **基本信息编辑**（姓名/头衔/简介/风格/部门，保存即 Toast+刷新）
  ② **工具授权管理**：来自真实注册目录的 9 工具，勾选/全选/清空，**三态展示：员工已授权 / 全局策略允许 / 实际可执行（五层诊断 available+原因，如"未授权工作区"）**——明确传达"勾选 ≠ 可执行"；变更 diff 预览；保存失败保留草稿
  ③ **工作区授权管理**：公司工作区列表（含 grants 回显、根目录、状态），授权只读/读写、撤销，全部走既有 grant API
- 共享 Toast 组件（`components/Toast.tsx`），监控页同步换用

**验证（Mock，0 真实费用）**：新增 `tests/test_employee_config.py` 8 个——默认白名单空（最小权限默认值）/增删持久化/非法名 422（两路径）/去重/工作区授权→五层诊断 available=true→撤销→false（reason=workspace_not_granted）/跨公司拒绝/不存在资源 404/Mock 端到端任务（API 配置好的员工真实执行文件读取成功）。

## 6. 附带发现并修复：用户 .env 泄漏进测试进程

全量回归时 3 个测试突然失败（"默认工具开关 off"假设的测试全部变 on）。根因：`create_app` 的 `load_dotenv` 把用户 `.env` 新配置的 `AGENTOS_TOOL_EXECUTION=on` 注入了**测试进程**。修复：conftest 的 autouse fixture 固定 `AGENTOS_MODEL_MODE=mock` 与 `AGENTOS_TOOL_EXECUTION=off`（需要 on 的测试显式覆盖）。另修正测试夹具中的假工具名 `file.write` → 真实名 `fs.write_file`。已记入 HANDOFF 坑清单。
