# M1 产品需求文档：AI 员工与组织管理体系

> 版本：v1.0（待用户确认）｜2026-11-05
> 上游依据：`M0_FINAL_HANDOFF.md`、`docs/product/PRD.md`、`docs/development/ROADMAP.md`
> 核心命题：**组织关系必须能影响任务分配与协作；员工必须有真实可执行的职责与权限，而不是 UI 上的角色名。**

---

## 1. 目标与非目标

### 1.1 目标（M1 结束时必须成立）

1. 用户能在 5 分钟内从零建起一家"公司"：部门、岗位、3 个员工、2 个模型连接，并让组织图正确反映汇报关系。
2. 员工身份与模型彻底解耦：同一模型可服务多个员工；同一员工可切主备模型；切换后历史记录、绩效、提示词版本全部保留。
3. 每个员工的有效权限可计算、可解释、可审计：来自"公司策略 ∩ 岗位默认 ∩ 员工覆盖"，且只能逐层收窄。
4. 组织关系可被程序消费：给定一个任务需求，系统能产出带理由的候选人排序（派工预览），并能沿汇报链推导出审查人。
5. 所有能力有真实后端 + 持久化 + 测试；前端只是这些能力的界面，不做假数据演示。

### 1.2 非目标（M1 明确不做）

| 不做 | 原因 / 归属 |
|---|---|
| 真实任务派发、任务状态机运行 | M2（M1 只交付"派工预览"服务与 API，不接 task-engine 执行） |
| 会议室、多 Agent 讨论 | M4 |
| 独立审查报告、返工闭环 | M3（M1 只推导"谁是审查人"，不执行审查） |
| 云端账号、设备注册 | M5 |
| 多用户 / SaaS 租户切换 | M6 预留 `owner_id`，M1 单用户 |
| MCP 工具实际执行 | M2；M1 只在权限档案里登记工具白名单 |
| CLI 员工真实执行 | 依赖 V7 解除；M1 允许录入 CLI 员工并做能力声明，执行留 M2 |

## 2. 领域概念（M1 定稿）

| 概念 | 定义 | 关键约束 |
|---|---|---|
| 公司 Company | 组织根节点，承载策略与预算 | 可有多个；M1 至少 1 个 |
| 部门 Department | 树形结构，可嵌套 | 同公司内名称唯一；不得成环 |
| 岗位 Position | 职责模板，可绑定部门或跨部门 | 一个员工可兼多岗（1 主 + n 兼） |
| 员工 Employee | AI 员工身份 = 档案 + 提示词 + 权限 + 模型引用 | 必须有公司；必须有主模型连接；不得自改权限 |
| 模型连接 ModelConnection | 可测试的连接配置（provider/model/base_url/凭据引用） | 被员工引用时不可直接删除 |
| 提示词 PromptRevision | 员工提示词的不可变版本，文件存盘 | 只能新增版本，不能原地改历史 |
| 权限档案 PermissionProfile | 员工级权限覆盖项 | 只收窄，不扩权 |
| 派工决策 AssignmentDecision | 一次候选人排序与选择理由 | 只增不改，可审计 |

## 3. 用户故事与验收条件

### US-1 公司管理
作为用户，我可以创建/重命名/归档公司，并看到该公司下的部门数、员工数、模型连接数。
**验收**：创建后列表实时出现；归档公司后其下员工全部不可派单（`status=disabled` 联动只读标记），数据不删除；有测试覆盖。

### US-2 部门树
我可以创建多级部门、拖拽调整上下级、删除空部门。
**验收**：拖拽后组织图与数据一致；把部门拖到自己的子部门下被拒绝并给出明确错误（BR-04）；含员工的部门删除被拒绝并提示先迁移（BR-05）。

### US-3 岗位与兼任
我可以创建岗位（如"技术审查官"），设置职责描述与默认权限，把员工安排到岗位，并允许一个员工兼任多个岗位。
**验收**：员工的"主岗"唯一；兼任岗位不叠加权限（取并集后仍与公司策略取交集——见 M1_SECURITY.md）；组织图节点显示主岗、悬浮显示兼任。

### US-4 员工 CRUD 与启停
我可以创建员工（姓名/头像/岗位/部门/简介/性格/职责），编辑、停用、启用、删除。
**验收**：创建走 3 步向导且必填校验完整；停用员工不能出现在派工候选人中；删除为软删除（保留审计），已产生运行记录的员工删除后历史仍可查。

### US-5 员工-模型解耦
我可以给员工指定主模型与备用模型，并在不改变员工身份的前提下切换；同一模型连接可被多个员工引用。
**验收**：
- 切换模型后 `employee.id` 不变，历史 `agent_run` / `usage_record` 仍归属该员工，且记录当时使用的模型（不能"追溯改写"）
- 删除被引用的模型连接被拒绝
- 两个员工引用同一模型连接，各自运行记录互不串（有测试）
- 切换写入 `model_switch_log`（谁、从什么到什么、原因）

### US-6 模型连接管理
我可以新增 OpenAI 兼容/DeepSeek/Anthropic 等连接，做连接测试，查看可用模型列表，设置超时与重试。
**验收**：连接测试真实发起一次最小调用并记录延迟与结果；密钥仅以引用形式存储（`env:DEEPSEEK_API_KEY`），响应与日志永不回显；测试失败给出可读原因（认证失败/网络/模型不存在分类）。

### US-7 员工提示词外置与版本化
我可以查看/编辑员工提示词，保存即生成新版本，可回滚到旧版本；运行时（M2）按激活版本加载。
**验收**：提示词存为 `data/prompts/employees/<employee_id>/vNNNN.md`（含 frontmatter）；编辑生成 v(N+1)，旧版本文件不被修改（有哈希校验）；回滚 = 切换 active 指针，不复制文件；文件缺失/哈希不符时加载失败并报错，不静默用空提示词。

### US-8 组织图编辑
我可以在组织图上看到公司→部门→岗位→员工的层级与汇报线，并直接拖拽员工调动部门/调整汇报对象。
**验收**：拖拽调部门立即持久化；调整汇报对象时若造成环（A→B→A）被拒绝；组织图布局在 50 节点内可读（性能基线见 M1_PLAN）。

### US-9 权限面板
我可以看到某员工的"有效权限"及其来源（公司策略/岗位默认/员工覆盖三层），并修改员工级覆盖。
**验收**：有效权限计算有单元测试覆盖三层交集；界面明确标出每一项来自哪一层；任何"放宽"操作会被公司策略层拦截并解释原因。

### US-10 配置导入导出
我可以导出团队配置（公司/部门/岗位/员工/模型连接元数据/提示词）为单个 zip 包，并在另一台机器导入。
**验收**：导出包不含任何明文密钥（只含 `api_key_ref`）；导入提供 dry-run 预览（将新建/覆盖/跳过多少项）；往返导入导出后组织结构与提示词哈希一致（有测试）。

### US-11 派工预览（组织影响分配的最小可验证形态）
我给定一个任务需求（需要什么能力、什么工具、风险等级），系统返回候选人排序与理由，并可指定"谁审查"。
**验收**：候选人只能来自硬过滤后的集合；排序分数可解释（每项权重可见）；审查人不等于执行人（BR-10）；决策落 `assignment_decision` 表。

### US-12 审计
我可以按员工/操作类型查看配置变更与权限相关操作记录。
**验收**：员工增删改、权限变更、模型切换、提示词发布、导入导出均留痕；记录不可修改（只增）。

## 4. 业务规则（编号供测试引用）

| 编号 | 规则 |
|---|---|
| BR-01 | 员工必须属于一个公司，且必须有 `primary_model_id` |
| BR-02 | 部门名称在同公司内唯一；岗位名称在同公司内唯一 |
| BR-03 | 部门树最大深度 8 层，超出报错 |
| BR-04 | 部门/汇报关系不得成环 |
| BR-05 | 含在册员工的部门不可删除（先迁移或停用员工） |
| BR-06 | 被员工引用的模型连接不可删除（可停用） |
| BR-07 | 提示词版本不可变；编辑即新增版本；激活版本必须存在且哈希校验通过 |
| BR-08 | 停用员工不进入派工候选；其名下未完成任务由 M2 转派（M1 不处理任务） |
| BR-09 | 有效权限 = 公司策略 ∩ 岗位默认 ∩ 员工覆盖，逐项取更严值，不允许任何一层扩权 |
| BR-10 | 审查人不得等于执行人；同部门"开发-测试"配对需不同模型供应商（跨模型审查）优先 |
| BR-11 | 密钥只存引用（`env:` / `dpapi:` / `keyring:`），任何 API 响应、日志、导出包不得出现明文 |
| BR-12 | Agent 侧不提供任何可修改员工/岗位/权限/模型绑定的接口（物理隔离，见 M1_SECURITY.md） |

## 6. 成功度量（M1 验收时量化）

| 指标 | 目标 |
|---|---|
| 建一家 3 员工公司的手工操作步数 | ≤ 20 次点击（含 2 个模型连接） |
| 有效权限计算一致性 | 单元测试覆盖三层组合 ≥ 12 组用例，全部通过 |
| 派工预览可解释性 | 每个候选人输出 ≥ 4 项打分因子与硬过滤原因 |
| 导入导出往返 | 组织结构 + 提示词哈希 100% 一致 |
| 回归 | M0 的 7 个测试 + M0 验证脚本 V1/V3/V5/V6 不回归 |
