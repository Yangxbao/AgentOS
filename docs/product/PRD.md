# AgentOS 产品需求文档（PRD）

> 版本：v0.1（M0）｜2026-11-05
> 本文档中：【已确认】= 产品负责人已拍板；【设计建议】= 本团队提出待确认；【已验证】= 经竞品调研或实测支撑；【未验证】= 假设

---

## 1. 产品定位【已确认】

AgentOS（AI 数字员工协作操作系统）是一个支持多模型、多 Agent、多运行环境的 AI 团队管理与协作平台。用户像经营真实公司一样创建 AI 公司、招聘 AI 员工、设置组织架构，让 AI 团队在半自主（关键节点人工审批）模式下完成任务。

**核心理念**：不是多 AI 同时答题，而是具备组织结构、任务管理、协作、监督、执行和交付能力的 AI 数字公司。**真正能干活的 AI，而不是看起来很热闹的 AI。**

## 2. 已锁定的产品决策【已确认，不重复讨论】

| 决策项 | 结论 |
|---|---|
| 产品方向 | AI 数字公司 + 多 AI 协作工作台 |
| 自主程度 | 半自主，关键节点用户审批 |
| 部署方式 | Windows 本地 + 云端（本地优先，云端不破坏本地） |
| AI 接入 | API + CLI 双接入，统一 Adapter |
| 组织结构 | 用户自由创建/修改，不写死 |
| 模型选择 | 不绑定单一供应商 |
| 安全策略 | 默认最小权限，重要操作人工审批 |
| 最终目标 | 可运行、可扩展、可开源（MIT） |

## 3. 目标用户与核心场景【设计建议】

**主用户**：独立开发者 / 小型技术团队负责人 / AI 重度使用者，已拥有多个模型 API Key 和 CLI 工具订阅，希望把"自己当项目经理带多个 AI"的手工流程产品化。

**核心场景**：
1. **开一家 AI 软件公司**：CEO（强模型）接需求 → 拆任务 → 分给开发员/测试员 → 测试员独立验证 → 不合格打回返工 → 用户验收
2. **跨模型交叉审查**：GPT 写的方案由 DeepSeek/Claude 员工审查，避免单一模型自证
3. **CLI 员工编进组织**：Codex 作为"高级开发员"被 CEO 派活，其文件操作走审批中心
4. **成本经营**：按员工看 Token/费用/通过率，用事实决定谁当 CEO

## 4. 十大子系统需求

> 每个子系统标注里程碑归属。详细功能见 FEATURE_MATRIX.md。

### 4.1 AI 员工中心（M1）
员工与模型**解耦**：员工 = 身份（名称/岗位/性格/提示词/权限）+ 模型连接引用（主模型 + 备用模型）+ 工具授权 + 独立记忆与执行记录。同一模型可支撑多个员工；一个员工可配置多个可切换模型。支持增删改、启停、运行历史、能力评估【已确认】。
设计借鉴：角色三要素（CrewAI）+ `*.agent.md` 文件格式（Cebus）【已验证-调研】。

### 4.2 AI 公司组织管理（M1）
多公司、部门、岗位、上下级关系全自定义；支持兼任、调动；React Flow 可视化组织图。禁止写死 CEO/开发/测试预设结构【已确认】。

### 4.3 多模型接入中心（M0 验证 → M1 产品化）
- API：经 LiteLLM 统一接入（OpenAI/Anthropic/Gemini/DeepSeek/OpenRouter/Ollama/自定义 OpenAI 兼容端点）【已验证：LiteLLM 供应商列表】
- CLI：Codex 官方 SDK / Claude Code / Gemini CLI / Copilot SDK / 自定义 CLI Adapter，全部经官方允许接口【已确认】
- 模型连接与员工身份分离；统一接口；连接测试；超时重试；**故障回退**；费用/Token 统计；状态显示
- 红线：不假设订阅=API 额度；不逆向、不抓会话、不绕认证【已确认】

### 4.4 AI 任务调度中心（M2）
CEO Agent 接目标→澄清→拆解→建依赖→派工→监控→汇总。支持顺序/并行/子任务/依赖/暂停/恢复/取消/重试/人工接管。**任务与执行记录分离**：同一任务可有多次执行记录，历史不覆盖【已确认】。
实现内核：LangGraph 图 + checkpointer【设计建议，M0 验证中】。

### 4.5 AI 会议室（M4）
多 AI 讨论、用户参与、@员工、CEO 召集、主持人、纪要、结构化决策、异议处理、决策转任务。**会议由任务调度系统控制开始/结束与成果转化，禁止无限循环群聊**【已确认】。

### 4.6 AI 监督中心（M3，产品最重要的功能之一）
上级监督下级 + 独立审查 Agent + 跨模型交叉审查 + 评分 + 审查报告 + 否决 + 自动退回 + 返工次数限制 + 最终验收。
**开发员不能自证代码无问题；测试员必须有独立验证能力。**
审查报告必含：结论/问题清单/严重程度/证据/修改建议/下一步动作。禁止只输出"通过/未通过"【已确认】。

### 4.7 共享工作空间（M2）
按项目隔离：文件/代码/文档/任务产物/日志/纪要/知识库/决策历史/附件。Agent 按授权访问，**禁止默认开放整个电脑**。本地工作空间由用户主动选择，默认只操作指定项目目录【已确认】。
设计借鉴：Git 仓库即代码任务协作总线 + result.json 原子哨兵（HALF）【已验证-调研】。

### 4.8 人工审批中心（M2 基础 → M3 完善）
覆盖：改文件、删文件、高危终端命令、装软件、上传云端、改系统配置、发布代码、部署服务、未授权工具。审批记录可追溯；**Agent 不能批准自己的高危操作；Agent 间互相授权不得突破用户授权边界**【已确认】。
实现借鉴：LangGraph interrupt/resume（API 侧）+ Copilot 式 permission handler 回调（CLI 侧）【已验证-调研】。

### 4.9 成本与绩效中心（M3）
按员工统计：任务数/成功/失败/返工次数/审查通过率/模型调用次数/Token/API 费用/平均任务时长/人工纠错次数。**模型能力由实际任务表现评估，不按模型名分配职位**【已确认】。
实现：LiteLLM completion_cost + 员工级归因映射【设计建议】。

### 4.10 团队模板与扩展生态（M6，后置）
团队配置导入导出、组织模板分享、Agent 插件、MCP 工具市场、A2A 连接、开发者 SDK。不得影响 M0–M5【已确认】。

## 5. 关键非功能需求

| 类别 | 需求 |
|---|---|
| 安全红线 | 十六条红线（立项文档第七节）为最高优先级，全文强制执行 |
| 本地优先 | 本地模式不依赖云；断网可用（除模型调用）；云端功能是增量 |
| 可恢复 | 关键任务持久化、断点恢复、重启不丢数据 |
| 可审计 | 状态变更全留痕，审批可追溯，API Key 不落日志 |
| 反失控 | Agent 不允许无限循环；模型调用有预算上限；返工有次数上限 |
| 模块化 | Monorepo 多包，禁止巨型单体文件 |
| 开源标准 | README/LICENSE(MIT)/CONTRIBUTING/CoC/SECURITY/CHANGELOG/CI 齐全 |

## 6. 任务状态机（核心领域模型，M0 设计 → M2 实现）

```
待规划 → 计划待审批 → 已批准 → 执行中 → 独立审查 → 审查通过 → 最终验收 → 已完成
              ↓拒绝        ↓失败      ↓退回(≤N次)
            重新规划      执行失败    执行中(返工)
旁路状态：已暂停 / 已取消 / 等待用户输入 / 等待权限审批 / 超出预算
```

**铁律**：状态变更只由后端执行；AI 自称"完成"不改变状态【已确认】。

## 7. 成功度量（M1 之后的北极星指标）【设计建议】

1. **任务一次通过率**（审查通过/总任务）——衡量团队真实交付力
2. **端到端交付率**：用户目标 → 无需人工纠错 → 验收完成的比例
3. **单任务平均成本**（Token + API 费用）
4. **审批响应时延**（用户侧体验关键）

## 8. 明确不做（本阶段）

- 不做无限自主（无审批的全自动模式）
- 不做移动客户端
- 不做模型训练/微调
- M0–M1 不做多用户 SaaS 化（单用户本地优先，schema 预留多租户）
- 不内置任何需要逆向/绕认证的接入
