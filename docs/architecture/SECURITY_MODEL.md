# AgentOS 安全模型

> v0.1｜2026-11-05｜十六条安全红线的工程落地
> 原则：默认最小权限；用户拥有最终控制权；Agent 永不自批；信任边界显式化

## 1. 信任边界

```
[用户]  ←唯一信任源，所有权限的授予者
  │
[apps/api 后端]  ← 权限裁决点（策略引擎 + 审批中心）
  │  ↓ 按员工最小授权
[Agent 执行体（API 模型 / CLI 子进程）]  ← 不可信
  │  ↓ 更窄的授权
[MCP server / 自定义 CLI / 插件]  ← 最不可信
  │
[云端控制平面]  ← M5，默认不信任：本地明确注册+授权前零通信
```

## 2. 红线 → 工程措施映射

| # | 红线 | 工程措施 |
|---|---|---|
| 1-2 | 不扫描/修改整台电脑、不默认读全盘 | 工作空间白名单：Agent 文件访问仅经 workspace 服务，路径规范化后校验前缀必须在授权 root 内；`..` 逃逸直接拒绝并审计 |
| 3 | 不自动删文件 | file_delete 属高危动作，默认走审批；审批 UI 强制显示完整路径清单 |
| 4 | 不自动装软件 | software_install 高危；M0–M4 不提供自动安装能力 |
| 5-6 | 不关 Defender/防火墙、不加排除项 | 命令黑名单硬编码（Set-MpPreference、netsh advfirewall、ExclusionPath 等模式），命中即拒绝，不可配置关闭 |
| 7 | 不改系统环境变量 | setx/注册表 Environment 键写入列入黑名单 |
| 8 | 不绕官方授权认证 | CLI 仅官方 SDK/headless 接口；Adapter 接入评审清单含"认证方式合规"检查项 |
| 9 | API Key 不明文落日志 | 密钥只存环境变量名/密钥引用；日志管道统一脱敏过滤器（sk-*/Bearer/key 正则）；usage 事件入库前脱敏 |
| 10 | 本地文件不自动上传云端 | 上传动作独立 action_type=cloud_upload，逐次审批；Connector 默认仅同步元数据 |
| 11-13 | 不自提权、不自批、Agent 互授权不越界 | approval_request.decided_by DB CHECK='user'；审批服务无 Agent 可调用的 decide API；权限来源链校验：任何 Agent 权限可回溯到一次用户授权，链断即拒绝 |
| 14-15 | 不无限循环、不无限调用模型 | 三层护栏：任务 max_steps / agent_run 时长上限 / 任务与员工级预算（超限→over_budget 状态，停） |
| 16 | 未授权不执行任意终端命令 | 命令白名单+黑名单双层；未匹配命令默认转审批 |

## 3. 审批风险分级【设计】

| 等级 | 例子 | 要求 |
|---|---|---|
| low | 读工作空间内文件 | 免审批（在白名单内） |
| medium | 写工作空间内文件、安装项目依赖（npm install） | 可配置：默认审批，用户可按"本次会话记住"放宽 |
| high | 删文件、git push、访问工作空间外路径、网络上传 | 必须逐项审批，显示完整参数 |
| critical | L3 完全访问、系统配置、服务部署、发布 | 逐项审批 + 二次确认 + 完整后果说明 |

## 4. 凭证管理【设计】

- `.env` 仅存密钥引用（`DEEPSEEK_API_KEY`），`.env` 在 .gitignore 且 .env.example 只含键名
- model_connection.api_key_ref 存环境变量名；运行时从进程环境解析，永不写库、永不进事件流
- 云端模式（M5）：密钥默认留在本地 Connector，云端只下发任务；如用户选择云端代管密钥，需单独加密存储（KMS 信封加密）+ 显式授权——此功能默认关闭

## 5. 审计

- audit_log 只增不改；记录：actor（user/agent/system）、动作、目标、参数摘要（脱敏）、结果、时间
- 高危操作三要素永远可查：谁发起（agent_run）→ 谁批准（user）→ 执行结果（task_event）
- 审批 UI 提供"该 Agent 历史审批记录"面板，辅助用户判断

## 6. 提示词注入缓解【设计，M2 起逐步落实】

- 工具返回内容/外部文档作为"不可信数据"包装注入（分隔标记 + 指令重申）
- 审查 Agent 的输入与执行 Agent 的输出通道隔离，防止成果文本里藏指令污染审查
- 跨员工消息传递经 task-engine 结构化字段，不直接拼接进对方 system prompt

## 7. 已知未解决项【诚实声明】

- Windows 上 CLI 子进程沙箱强度弱于 Linux seccomp：当前依赖 CLI 自身沙箱（Codex 已验证三档）+ Job Object 限制，不等于 OS 级强制隔离【未验证】
- 提示词注入无法根治，第 6 节是缓解不是消除
- MCP server 生态质量参差，工具市场（M6）需要审核机制，当前默认仅启用用户显式配置的 server
