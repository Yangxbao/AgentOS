# 本地-云端协同架构（AgentOS Connector）

> v0.1｜2026-11-05｜M5 实施，本文定信任边界与协议骨架
> 铁律：本地优先——无云端账号时 AgentOS 功能 100% 可用；云端是可选增强

## 1. 形态

```
┌─ 云端控制平面（可选）────────────────────┐
│ 账号/团队空间/跨设备看板/模板市场          │
│ 任务下发队列 · 设备注册表 · 结果归档        │
└──────▲───────────────────────────────────┘
       │ WSS（TLS + 设备证书）—— 仅 Connector 主动外连
┌──────┴── 用户设备 ───────────────────────┐
│ AgentOS Connector（随 apps/api 运行的模块）│
│  · 设备注册/心跳/任务拉取/事件上报          │
│  · 本地裁决点：云端请求在此接受本地策略复核   │
│ apps/api（本地完整功能） + SQLite + 工作空间 │
└───────────────────────────────────────────┘
```

## 2. 信任边界（安全模型的云端延伸）

1. **云端永远不可信直达执行**：云端下发的任务与本地用户创建的任务走**同一个任务引擎和审批中心**，云端身份 = 一个权限受限的"远程用户"角色
2. **本地文件默认不出设备**：云端只同步：任务元数据、状态、用户显式授权的产出物（逐次或按规则授权）
3. **凭证不出设备**：API Key 保留在本地；云端代管密钥功能默认关闭（见 SECURITY_MODEL 第 4 节）
4. **断连即本地自治**：云端不可达时所有本地功能正常；未完成任务继续跑，事件本地积压、恢复后补传
5. **撤销即失效**：设备授权撤销后，云端持有该设备的证书作废，队列中未执行任务标记 abandoned

## 3. 核心流程【设计】

### 3.1 设备注册
```
用户在本地 UI 点"连接云端" → 输入云端账号 → 本地生成设备密钥对
→ 云端显示设备名 + 公钥指纹 → 用户在云端确认绑定
→ 云端签发设备证书（短有效期，自动轮换）
```
借鉴 A2A Agent Card 思想：设备注册即发布一份 Device Card（设备名/能力/AgentOS 版本/网络条件）【设计】。

### 3.2 任务下发
```
云端任务 → 队列 → Connector 拉取 → 本地策略复核（是否允许远程任务？预算？）
→ 转本地 task（origin=cloud）→ 正常走状态机/审批（审批仍可要求本地用户）
→ 事件流本地落库 + 按需上报云端（脱敏）
```

### 3.3 断线恢复
- 上报采用"本地事件日志 + 云端已收游标"，重连后从游标补传（借鉴 A2A Resubscribe 语义【已验证-调研】）
- 云端→本地方向：任务下发幂等（task_uuid 去重）

## 4. 同步内容白名单【设计】

| 数据 | 默认 | 可授权项 |
|---|---|---|
| 任务/员工/组织的元数据（名称、状态、成本数字） | ✅ 同步 | — |
| 执行事件摘要（脱敏后） | ✅ 同步 | — |
| 任务最终产出物 | ❌ 不同步 | 逐任务授权上传 |
| 工作空间任意文件 | ❌ 不同步 | 逐文件/目录授权 |
| 会话原文/prompt 全文 | ❌ 不同步 | 用户显式开启"详细同步" |
| API Key / CLI 凭证 | ❌ 永不 | 无此选项（代管密钥是独立的显式功能） |
