## 第 1 章　认识 AgentOS

> 一句话定位：AgentOS 是你的 AI 数字公司操作系统——你当老板，AI 员工干活，你签收成果。

### 1.1 AgentOS 是什么

AgentOS 不是聊天工具，而是一个"AI 公司"操作系统。在这个系统中：

- **每个 AI 员工都有独立身份**：包括姓名、头像、岗位、职责描述、权限范围和私有记忆
- **员工之间真实协作**：不是简单的对话接力，而是有组织架构、任务分配、依赖关系的流水线协作
- **互相验证机制**：不同岗位的员工会交叉检查彼此的工作成果，确保质量
- **你始终拥有最终签收权**：所有交付物都需要你的审批才能完成

> 📌 **核心隐喻**：把 AgentOS 想象成你经营的一家真实公司——你是老板，AI 员工是你的团队，任务是你派给他们的工作，审批是你验收成果的过程。

### 1.2 它能帮我做什么

AgentOS 可以自动完成从市场调研到产品交付的全流程工作，典型场景包括：

- **企业官网建设**：如星舟科技案例，7 名跨职能 AI 员工通过 9 步瀑布流水线完成五页响应式官网
- **网页应用开发**：包括前端界面、后端逻辑、数据库设计等完整交付
- **调研报告生成**：自动收集信息、分析数据、撰写专业报告

> **真实案例展示**：
>
> > 场景：为虚拟客户「星舟科技」交付企业官网
> >
> > 操作：7 名 AI 员工（调研/产品/UI 设计/文案/前端/测试/项目经理）协作执行
> >
> > 结果：五页响应式官网 + 共享 CSS/JS（16.8KB 首页），通过真浏览器逐页验收

### 1.3 与普通 AI 聊天工具的区别

| 对比维度 | 普通聊天工具 | AgentOS |
|---|---|---|
| **交互方式** | 单轮对话，每次都是全新开始 | 多员工流水线协作，上下文连续 |
| **审批机制** | 无审批，直接输出结果 | 双关卡审批：执行前审批 + 交付后审批 |
| **权限控制** | 无权限限制 | 五层权限体系，逐层收窄 |
| **记忆能力** | 无长期记忆 | 三级记忆：员工私有/项目/公司 |
| **交付验收** | 看文档猜测效果 | 审批卡片内嵌实际渲染效果 |

> 📌 **关键差异**：聊天工具像"问答机器"，AgentOS 像"完整团队"——前者回答问题，后者交付成果。

### 1.4 运行方式与安全承诺

AgentOS 采用本地优先架构，确保你的数据安全和隐私：

- **本地优先**：默认只监听 127.0.0.1，数据不出本机
- **Shell 禁用**：系统永久禁用命令执行，无代码注入风险
- **密钥安全**：API 密钥只存环境变量引用，不入数据库
- **全量审计**：所有操作都有留痕记录，便于追溯

> ⚠️ **安全红线**：AgentOS 没有命令执行路径，通过 AST 扫描证明；敏感文件（.env/密钥/ssh）直接拒绝访问。

## 第 2 章　快速开始

> 目标：30 分钟内从零到看到第一个任务执行结果。

### 2.1 系统要求

在开始之前，请确保你的环境满足以下要求：

- **操作系统**：Windows / macOS / Linux
- **Python**：3.13 版本
- **Node.js**：最新 LTS 版本
- **磁盘空间**：建议至少 1GB 可用空间
- **内存**：建议至少 4GB 可用内存

### 2.2 安装步骤

#### ① 后端安装

```bash
# 创建虚拟环境
python -m venv .venv
.venv\Scripts\activate              # Windows
# 或 source .venv/bin/activate      # macOS/Linux

# 安装依赖
pip install -r requirements.txt
pip install -e .

# 配置环境变量
copy .env.example .env              # Windows
# 或 cp .env.example .env           # macOS/Linux

# 初始化数据库
alembic upgrade head

# 启动 API 服务
python scripts/run_api.py --port 8000
```

#### ② 前端安装（另开终端）

```bash
cd apps/web && npm install && npm run dev
```

> 📌 **预期结果**：
> - 后端在 http://127.0.0.1:8000 运行
> - 前端在 http://127.0.0.1:5173 访问
> - 浏览器打开 http://127.0.0.1:5173 看到 AgentOS 界面

### 2.3 零成本体验（Mock 模式）

AgentOS 提供零成本体验模式，无需任何 API Key 即可完整运行：

- **Mock 模式**：不调用外部 AI 服务，所有内容由系统模拟生成
- **完全免费**：不计任何费用，适合熟悉界面和流程
- **功能完整**：可以体验组织架构、任务创建、审批等所有核心功能

> 📌 **适用场景**：
> - 熟悉界面操作
> - 理解任务执行流程
> - 培训团队成员
> - 验证功能完整性

### 2.4 接入真实 AI 模型

当你准备好使用真实的 AI 模型时，可以按照以下步骤接入：

#### ① 获取 API Key

以 DeepSeek 为例：
1. 访问 [DeepSeek 官网](https://platform.deepseek.com)
2. 注册并获取 API Key
3. 记录 Key 值备用

#### ② 配置环境变量

编辑 `.env` 文件，添加：
```
DEEPSEEK_API_KEY=your_api_key_here
```

#### ③ 切换执行模式

在 AgentOS 界面中，将执行模式从 `mock` 切换为 `real`

> 💰 **费用提示**：
> - Mock 模式：完全免费，系统模拟生成内容
> - Real 模式：根据实际调用量计费，建议先从小任务开始
> - 费用控制：可以设置任务预算上限，超限自动停止

### 2.5 第一个任务：让 AI 员工写一份市场调研

现在让我们创建第一个任务，体验完整的 AI 员工协作流程：

#### ① 建公司
- 点击"创建公司"
- 输入公司名称（如"我的AI公司"）
- 填写公司简介（可选）

#### ② 建 AI 员工
- 点击"添加员工"
- 设置员工信息：
  - 姓名：市场调研员
  - 头像：选择合适头像
  - 岗位：市场调研
  - 简介：负责市场调研和竞品分析
  - 性格：注重细节，先调研再动手

#### ③ 绑定 AI 模型
- 为员工选择 AI 模型（如 DeepSeek）
- 连接测试确保配置正确

#### ④ 创建任务
- 点击"创建任务"
- 任务标题："市场调研报告"
- 任务描述："请调研当前AI协作工具市场，分析主要竞争对手和产品特点"
- 指定负责人：市场调研员
- 设置优先级：高

#### ⑤ 查看执行
- 任务状态变为"执行中"
- 可以实时查看执行进度和步骤
- 系统会自动调用员工的能力完成调研

#### ⑥ 审批签收
- 任务完成后进入"待审批"状态
- 在审批卡片中查看调研结果
- 满意后点击"签收"，任务完成

## 第 3 章　建 AI 公司

> 核心隐喻：你是在"注册一家公司"——有名称、部门、岗位、员工。

### 3.1 创建公司

在 AgentOS 中，每家公司都是独立的组织单元：

- **公司名称**：给你的 AI 公司起个名字（如"创新科技"、"数字营销"等）
- **公司简介**：描述公司的业务方向和目标
- **多公司支持**：一台电脑可以管理多家公司，适合不同业务场景

> 📌 **操作步骤**：
>
> ① 点击界面上的"创建公司"按钮
> ② 填写公司名称和简介
> ③ 点击"确认创建"
>
> **预期结果**：公司创建成功，显示在组织架构列表中

### 3.2 搭建组织架构

像真实公司一样，你需要设计组织架构来管理 AI 员工：

#### ① 创建部门

- 产品部：负责产品规划和需求分析
- 设计部：负责UI设计和用户体验
- 开发部：负责代码实现和功能开发
- 测试部：负责质量保证和缺陷修复

> 📌 **部门创建**：
>
> > 场景：为星舟科技创建组织架构
> >
> > 操作：点击"添加部门" → 输入"产品部" → 点击"确认"
> >
> > 结果：部门创建成功，可以继续添加子部门

#### ② 定义岗位

每个部门需要设置具体的岗位：

- **产品部**：产品经理、需求分析师
- **设计部**：UI设计师、交互设计师
- **开发部**：前端开发、后端开发、全栈开发
- **测试部**：测试工程师、质量保证专员

#### ③ 设置上下级关系

- 部门之间可以设置层级关系
- 员工归属于特定部门
- 形成完整的组织架构图

> 📌 **组织架构特点**：
>
> - 可视化展示：点击部门可展开查看员工
> - 权限继承：下级自动继承上级的部分权限
> - 灵活调整：可以随时调整组织架构

### 3.3 招聘 AI 员工

AI 员工是公司的核心资产，招聘时需要考虑以下要素：

#### ① 员工四要素

- **姓名**：给员工起个容易识别的名字
- **头像**：选择合适的头像，便于识别
- **岗位**：明确员工的职责和工作范围
- **简介**：详细描述员工的工作内容和专长

> 📌 **员工创建示例**：
>
> > 场景：招聘前端开发工程师
> >
> > 操作：点击"添加员工" → 填写信息：
> > - 姓名：前端开发工程师
> > - 头像：选择技术风格头像
> > - 岗位：前端开发
> > - 简介：负责网页界面开发，熟悉HTML/CSS/JavaScript
> >
> > 结果：员工创建成功，显示在对应部门下

#### ② 性格与行为规则

为员工设置性格特点，影响其工作方式：

- **注重细节**：会仔细检查代码和设计
- **先调研再动手**：开始工作前会充分了解需求
- **追求完美**：对质量要求较高
- **效率优先**：注重完成任务的速度

#### ③ 系统提示词

用自然语言描述员工的工作方式：

```
你是一名专业的前端开发工程师，注重代码质量和用户体验。
接到任务时，先仔细阅读需求，然后制定实现方案。
开发过程中会考虑浏览器兼容性和性能优化。
完成后会进行自我测试，确保功能正常运行。
```

### 3.4 为员工分配能力

员工的能力需要严格控制，确保安全性和针对性：

#### ① 工具授权

决定员工可以使用哪些工具：

- **文件读写工具**：读取和编辑项目文件
- **HTTP 请求工具**：调用外部API获取数据
- **图片识别工具**：分析图片内容（如设计图）
- **工具全局开关**：可以随时启用或禁用特定工具

> 📌 **工具授权原则**：
>
> - 最小权限：只给员工完成任务必需的工具
> - 按需开放：根据任务复杂度逐步开放权限
> - 审计留痕：所有工具调用都有记录

#### ② 工作权限

设置员工的工作范围和限制：

- **代码执行权限**：是否允许运行代码
- **网络访问权限**：可以访问哪些域名
- **文件访问权限**：可以读写哪些目录
- **操作频率限制**：防止过度调用API

#### ③ 工作区授权

员工只能访问被授权的项目目录：

- **项目隔离**：不同项目的文件互相隔离
- **路径安全**：防止文件系统逃逸攻击
- **敏感文件保护**：自动拒绝访问敏感配置文件

### 3.5 为员工绑定 AI 模型

AI 模型是员工的核心能力，需要合理配置：

#### ① 员工与模型解耦

- **同一模型服务多个员工**：提高资源利用率
- **一个员工配主备模型**：主模型故障时自动切换
- **灵活配置**：可以根据任务需求调整模型

#### ② 已验证模型列表

AgentOS 已验证以下模型可用：

- **DeepSeek**：通用能力强，适合各类任务
- **智谱 GLM-4V/4.6V**：多模态模型，擅长图片理解
- **OpenRouter**：多模型聚合平台

#### ③ 连接测试方法

在绑定模型后，建议进行连接测试：

```bash
# 测试模型连接
curl -X POST "http://127.0.0.1:8000/api/test-model" \
  -H "Content-Type: application/json" \
  -d '{"model": "deepseek-chat"}'
```

> 📌 **模型配置提示**：
>
> - 主备模型配置确保服务连续性
> - 不同模型适合不同类型的工作
> - 定期测试模型连接状态

### 3.6 组织配置导入导出

为了便于管理和迁移，AgentOS 支持组织配置的导入导出：

#### ① 导出组织配置

将整套组织架构导出为配置文件：

```bash
# 导出当前公司配置
curl -X GET "http://127.0.0.1:8000/api/company/export" \
  -H "Authorization: ***REDACTED***" \
  -o company_config.json
```

#### ② 从配置文件重建公司

```bash
# 从配置文件重建公司
curl -X POST "http://127.0.0.1:8000/api/company/import" \
  -H "Content-Type: application/json" \
  -H "Authorization: ***REDACTED***" \
  -d @company_config.json
```

> 📌 **适用场景**：
>
> - **备份**：定期备份组织架构配置
> - **迁移**：将配置迁移到新环境
> - **分享**：分享团队组织模板给其他用户
> - **标准化**：确保多个项目使用相同的组织结构

## 第 4 章　任务与审批

> 核心隐喻：你是"老板派活 + 签收验收"——AI 员工执行，你把关质量。

### 4.1 创建任务

创建任务就像给员工下达工作指令，用自然语言描述即可：

- **任务标题**：简明扼要地概括任务内容（如"设计官网首页"）
- **任务描述**：详细说明需求，像给人类员工写工作邮件一样描述清楚
- **指定负责员工**：选择最合适的 AI 员工来执行
- **优先级**：高 / 中 / 低，决定任务排队顺序
- **截止时间**：设定预期完成时间

> 📌 **任务描述技巧**：
>
> > 场景：需要 AI 员工撰写产品介绍文案
> >
> > 操作：创建任务，描述写"请为星舟科技撰写产品介绍页文案，风格要求专业、科技感，突出商业航天领域的技术优势，字数 800-1200 字"
> >
> > 结果：员工根据详细描述产出符合要求的文案
>
> 描述越具体，交付物越符合预期。避免模糊指令如"写个文案"。

### 4.2 任务生命周期

每个任务都会经历完整的状态流转：

```
待分配 → 执行中 → 待审批 → 已签收
                  ↘ 已退回 → 执行中（返工）
```

- **待分配**：任务已创建，等待分配给员工
- **执行中**：员工正在执行任务
- **待审批**：员工提交成果，等待你签收
- **已签收**：你确认成果合格，任务完成
- **已退回**：你认为成果不合格，退回修改

> 📌 **自动恢复机制**：
>
> - **失败自动重规划**：任务执行失败时，系统会自动分析原因并重新规划执行路径
> - **断点续跑**：任务中断后，从最近的检查点恢复执行，而非从头开始

### 4.3 子任务与依赖

复杂任务可以拆解为多个子任务，并设置依赖关系：

- **大任务拆解**：将复杂项目拆分为可独立执行的子任务
- **依赖关系**：设置子任务之间的先后顺序（如：设计完成后才能开发）
- **并行执行**：没有依赖关系的子任务会同时执行，提高效率

> 📌 **依赖设置示例**：
>
> > 场景：建设企业官网
> >
> > 操作：创建子任务并设置依赖——
> > ① 市场调研（无依赖）
> > ② 产品规划（依赖①）
> > ③ UI 设计（依赖②）
> > ④ 文案撰写（依赖②，与③并行）
> > ⑤ 前端开发（依赖③④）
> > ⑥ 测试验收（依赖⑤）
> >

## 第 5 章　工具与安全

> 核心隐喻：你给员工"工位和工具箱"——规定能用什么、能访问什么。

### 5.1 工具总览

AgentOS 为 AI 员工提供以下工具：

| 工具 | 功能 | 默认状态 |
|---|---|---|
| **文件读写工具** | 读取和编辑项目文件 | 关闭 |
| **HTTP 请求工具** | 调用外部 API 获取数据 | 关闭 |
| **图片识别工具** | AI 看图提取设计规范（如从设计稿提取颜色、布局） | 关闭 |

> 📌 **工具全局开关**：所有工具默认关闭，你需要根据员工职责按需开启。这是安全设计的一部分——默认不给任何能力，按需授权。

### 5.2 五层权限体系

AgentOS 采用五层权限体系，像公司门禁一样逐层收窄：

```
① 全局开关（公司大门）
   → ② 公司策略（部门权限）
      → ③ 员工白名单（工位钥匙）
         → ④ 岗位权限画像（岗位资格）
            → ⑤ 工作区读写授权（文件柜钥匙）
```

| 层级 | 类比 | 说明 |
|---|---|---|
| ① 全局开关 | 公司大门 | 工具是否全局启用，关闭则所有员工都无法使用 |
| ② 公司策略 | 部门权限 | 公司级别的策略限制，如禁止访问某些域名 |
| ③ 员工白名单 | 工位钥匙 | 每位员工单独授权的工具列表 |
| ④ 岗位权限画像 | 岗位资格 | 根据岗位自动匹配的权限模板 |
| ⑤ 工作区读写授权 | 文件柜钥匙 | 员工可以读写哪些具体目录 |

> ⚠️ **权限规则**：五层权限缺一不可，最严层生效。即：即使员工白名单授权了某工具，如果全局开关关闭，该工具仍然不可用。

### 5.3 工作区与文件安全

工作区是项目级隔离空间，确保文件安全：

- **工作区隔离**：员工只能访问被授权的项目目录，无法跨项目访问
- **路径安全**：系统拒绝以下危险路径访问：
  - 绝对路径（如 `/etc/passwd`）
  - 盘符路径（如 `C:\Windows`）
  - 目录逃逸（如 `../../etc`）
  - 符号链接（防止通过软链接绕过限制）
- **敏感文件防护**：以下文件类型直接拒绝访问，无论权限如何设置：
  - `.env` 环境变量文件
  - 密钥文件（`.pem`、`.key` 等）
  - SSH 配置文件（`~/.ssh/` 目录下所有文件）

> ⚠️ **安全红线**：敏感文件防护是硬编码的安全规则，无法通过任何配置绕过。

### 5.4 网络请求安全

员工发起 HTTP 请求时，系统执行多重安全检查：

- **域名白名单**：只有白名单中的域名才允许访问
- **DNS 逐 IP 校验**：解析域名后逐个验证 IP 地址，防止 SSRF（服务器端请求伪造）攻击
- **重定向逐跳检查**：HTTP 重定向时，每一跳的目标地址都要通过白名单校验

> 📌 **配置建议**：在员工工具授权时，明确列出需要访问的域名，避免使用通配符白名单。

### 5.5 审计与熔断

AgentOS 提供完善的审计和熔断机制：

#### ① 全量操作审计

- 所有员工操作都有留痕记录
- 审计日志经过脱敏处理，不记录密钥和敏感数据
- 可按时间、员工、任务等维度查询审计记录

#### ② 预算熔断

- 设置任务预算上限（Token 或金额）
- 超出预算时自动停止任务执行
- 防止因模型异常导致费用失控

#### ③ 连续拒绝熔断

- 员工的操作被审批连续拒绝多次后，自动暂停该员工
- 防止员工在错误方向上持续消耗资源

#### ④ 全局紧急开关（Kill Switch）

- 一键停止所有正在执行的任务
- 紧急情况下的最后保障

> ⚠️ **熔断触发后**：任务暂停而非删除，你可以查看原因后决定恢复或取消。

### 5.6 高危操作审批清单

以下 9 类操作被定义为高危操作，必须经过你的审批才能执行：

| 类别 | 示例 | 审批要求 |
|---|---|---|
| 文件删除 | 删除项目文件 | 执行前审批 |
| 文件覆盖 | 覆盖已有文件 | 执行前审批 |
| 批量写入 | 一次写入多个文件 | 执行前审批 |
| 网络请求 | 调用外部 API | 根据域名策略 |
| 模型切换 | 切换使用的 AI 模型 | 执行前审批 |
| 预算超限 | 超出任务预算 | 自动熔断 |
| 权限变更 | 修改员工权限 | 执行前审批 |
| 数据导出 | 导出公司数据 | 执行前审批 |
| 配置修改 | 修改系统配置 | 执行前审批 |

> ⚠️ **红线规则**：AI 员工不可自批——任何需要审批的操作，员工都不能绕过审批自行执行。

## 第 6 章　记忆

> 核心隐喻：员工有"笔记本"——记住公司规范、项目经验、个人心得。

### 6.1 三级记忆作用域

AgentOS 的记忆系统分为三个作用域，从窄到宽：

| 作用域 | 类比 | 谁能读 | 典型内容 |

> 📌 **记忆优先级**：执行任务时，系统按"员工私有 → 项目 → 公司"的顺序检索相关记忆，将匹配的内容注入员工上下文。

### 6.2 记忆如何工作

记忆的检索和使用是自动化的：

- **自动检索**：员工执行任务时，系统自动检索与任务相关的记忆条目
- **中文 2-gram 全文检索**：基于 SQLite FTS5 实现的中文全文检索，支持分词匹配
- **上下文注入**：检索到的相关记忆自动注入员工的任务上下文，无需手动引用
- **手动管理**：你可以在记忆管理界面进行增删改查操作

> 📌 **记忆管理操作**：
>
> ① 进入记忆管理页面
> ② 选择作用域（员工/项目/公司）
> ③ 添加、编辑或删除记忆条目
> ④ 每条记忆包含：标题、内容、标签
>
> [截图：记忆管理界面]

### 6.3 记忆最佳实践

合理使用记忆可以显著提升员工表现：

#### 什么该记

- **公司品牌规范**：颜色、字体、语气等设计标准
- **项目技术约定**：框架版本、目录结构、命名规范
- **常见问题解法**：反复出现的问题及解决方案
- **客户偏好**：特定客户的风格和要求

#### 什么不该记

- **临时性信息**：一次性的、不会复用的数据
- **大段代码**：代码应放在项目文件中，记忆中只放引用路径
- **敏感信息**：密钥、密码等不应存入记忆

> 📌 **记忆精简原则**：记忆会占用员工的上下文空间，过多的记忆会导致上下文膨胀、检索精度下降。建议定期清理过时记忆，保持每条记忆精炼有用。

## 第 7 章　监督与质量

> 核心隐喻：有"质检部门"——上级监督下级、独立审查员交叉检查。

### 7.1 上级监督

AgentOS 的组织架构天然支持上级监督机制：

- **监督关系由组织架构决定**：上级自动监督下级的交付物
- **监督内容**：上级员工会检查下级的工作是否符合要求
- **监督反馈**：上级发现问题会给出修改建议，下级据此改进

> 📌 **示例**：
>
> > 场景：项目经理（上级）监督前端开发（下级）的交付
> >
> > 操作：前端开发提交代码后，项目经理自动收到审查请求
> >
> > 结果：项目经理检查代码质量，发现问题则退回修改，合格则提交给你审批

### 7.2 独立审查

对于关键交付物，AgentOS 支持独立审查机制：

- **独立审查 Agent**：专门负责质量检查的 AI 员工，不参与开发过程
- **开发员不可自证**：开发员工不能自己审查自己的工作，必须由独立审查员检查
- **跨模型交叉审查**：使用不同的 AI 模型进行复核，避免同一模型的认知盲区

> 📌 **跨模型审查的价值**：
>
> 同一模型可能对某些类型的错误"视而不见"（同模型盲区）。使用不同模型交叉审查，可以互补发现更多问题。例如：用 DeepSeek 开发、用智谱 GLM 审查。

### 7.3 审查报告

审查完成后，系统生成结构化审查报告，包含六要素：

| 要素 | 说明 |
|---|---|
| **结论** | 通过 / 不通过 |
| **问题** | 发现的具体问题列表 |
| **严重度** | 每个问题的严重程度（致命/严重/一般/建议） |
| **证据** | 支持问题判定的具体证据 |
| **建议** | 修改建议和改进方向 |
| **动作** | 需要执行的具体动作（自动退回/标记待修改/仅记录） |

> 📌 **审查结果处理**：
>
> - **否决**：审查结论为"不通过"时，任务自动退回执行员工修改
> - **最终验收**：由后端状态机裁决，确保状态流转的一致性和可靠性

### 9.1 多员工流水线协作

多员工流水线是 AgentOS 最强大的能力之一，以星舟科技官网案例说明：

#### 9 步瀑布流水线


- **依赖关系设置**：每步依赖前序步骤的输出作为输入
- **并行优化**：无依赖的步骤并行执行（如 UI 设计和文案撰写可同时进行）
- **上下文交接**：前序员工的工作成果自动传递给后续员工

> 📌 **流水线配置要点**：

> - 合理设置依赖关系，避免不必要的串行等待
> - 在任务描述中明确说明输入和输出格式，确保上下文交接顺畅
> - 为关键节点设置审批检查点

### 9.2 用 AI 看图驱动开发

AgentOS 支持视觉驱动的开发流程：

- **视觉质检员**：AI 员工通过图片识别工具查看设计稿，提取颜色、布局、字体等规范
- **前端按规范实现**：开发员工根据提取的设计规范编写代码，确保实现与设计一致
- **实测模型**：智谱 GLM-4V 和 GLM-4.6V 在图片理解方面表现优秀，推荐用于视觉质检

> 📌 **视觉驱动流程**：
>
> > 场景：根据设计师提供的设计稿开发网页
> >
> > 操作：
> > ① 将设计稿图片上传到项目工作区
> > ② 视觉质检员使用图片识别工具提取设计规范
> > ③ 前端开发员根据规范实现代码
> > ④ 视觉质检员对比实现效果与设计稿
> >
> > 结果：前端实现与设计稿高度一致

### 9.3 主备模型与故障自愈

为员工配置主备模型可以提升服务可靠性：

- **主模型故障自动切换**：主模型调用失败时，系统自动切换到备模型继续执行
- **max_tokens 超限自动降级**：当模型返回的 Token 数超过限制时，自动降级处理
- **配置建议**：
  - 主模型选择能力最强的通用模型（如 DeepSeek）
  - 备模型选择稳定性高的模型
  - 两个模型最好来自不同供应商，避免单点故障

> 📌 **主备配置示例**：
>
> - 主模型：DeepSeek（通用能力强）
> - 备模型：智谱 GLM-4（稳定性好）
> - 当 DeepSeek 调用失败时，自动切换到 GLM-4 继续执行

### 9.4 多 Worker 部署

对于需要大量并行处理任务的场景，AgentOS 支持多 Worker 部署：

- **租约与心跳机制**：Worker 通过心跳向主服务报告存活状态，租约到期后任务可被其他 Worker 认领
- **原子认领**：任务分配采用原子操作，防止多个 Worker 重复执行同一任务
- **崩溃恢复**：Worker 崩溃后，其未完成的任务会被其他 Worker 接管
- **适用场景**：多台机器并行处理大量任务，提升整体吞吐量

> ⚠️ **多 Worker 部署需要一定的运维能力**，建议在单 Worker 模式运行稳定后再考虑扩展。

### 9.5 重启恢复

AgentOS 具备完善的崩溃恢复机制：

- **检查点机制**：任务执行过程中定期保存检查点
- **服务重启后自动恢复**：服务重启后，未完成的任务从最近的检查点恢复执行
- **数据持久化**：基于 SQLite WAL 模式，确保数据写入的原子性和一致性

> 📌 **恢复行为**：重启后，处于"执行中"的任务会自动恢复，不会丢失进度。

### 9.6 自定义员工行为

通过系统提示词和行为规则，你可以深度定制 AI 员工的工作方式：

#### 系统提示词编写技巧

- **明确角色定位**：开头说明员工的专业身份和核心职责
- **规定工作流程**：描述接到任务后的标准工作步骤
- **设定质量标准**：明确交付物的质量要求
- **提供注意事项**：列出需要避免的常见错误

#### 常见角色模板

| 角色 | 系统提示词要点 |
|---|---|
| **产品经理** | 先理解需求再规划，输出结构化产品方案，关注用户价值和可行性 |
| **设计师** | 遵循品牌规范，注重视觉一致性和用户体验，输出设计规范文档 |
| **开发工程师** | 代码质量优先，遵循项目技术栈和编码规范，完成后自测 |
| **测试工程师** | 全面覆盖功能测试，关注边界条件和异常情况，输出结构化测试报告 |
| **项目经理** | 协调各角色协作，把控进度和质量，及时上报风险 |

> 📌 **行为规则示例**：
>
> ```
> 性格：注重细节、追求完美
> 行为规则：
> - 接到任务后先完整阅读需求，不理解的部分主动询问

> - 交付前做最终检查，确保无遗漏
> ```

## 第 10 章　常见问题（FAQ）

### 10.1 安装与启动

**Q：端口被占用怎么办？**

A：后端默认使用 8000 端口，前端默认使用 5173 端口。如果端口被占用：
- 后端：启动时通过 `--port` 参数指定其他端口，如 `python scripts/run_api.py --port 8001`
- 前端：修改 `vite.config.ts` 中的端口配置

**Q：依赖安装失败常见原因？**

A：
- Python 版本不匹配：确认使用 Python 3.13
- 网络问题：尝试使用国内镜像源，如 `pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple`
- Node.js 版本问题：确认使用最新 LTS 版本

**Q：前后端连接不上怎么排查？**

A：
- 确认后端服务已启动（访问 http://127.0.0.1:8000/docs 查看是否返回 API 文档）
- 确认前端配置的后端地址正确
- 检查防火墙是否阻止了本地端口通信

### 10.2 模型与费用

**Q：支持哪些模型？**

A：目前已验证可用的模型包括：DeepSeek、智谱 GLM-4V/4.6V、OpenRouter。详见附录 C。

**Q：为什么任务费用比预期高？**

A：可能的原因：
- 任务复杂度超出预期，导致多轮交互
- 员工记忆注入增加了上下文长度
- 子任务数量较多，每个子任务都有独立消耗

**Q：如何控制成本？**

A：
- 设置任务预算上限（参见 8.2 节）
- 精简记忆内容，减少上下文长度
- 使用 Mock 模式进行测试，确认流程无误后再切换 Real 模式

**Q：Mock 模式和真实模式的区别？**

A：

| 维度 | Mock 模式 | Real 模式 |
|---|---|---|
| AI 调用 | 不调用外部 AI 服务 | 调用真实 AI 模型 |
| 内容质量 | 系统模拟生成，质量有限 | AI 生成，质量较高 |
| 费用 | 完全免费 | 按实际调用量计费 |
| 适用场景 | 熟悉流程、测试验证 | 实际生产使用 |

### 10.3 任务执行

**Q：任务一直卡在"执行中"怎么办？**

A：
- 查看执行时间线，确认卡在哪一步
- 检查员工是否在等待审批（执行前审批未通过）
- 检查模型连接是否正常
- 必要时暂停任务，排查问题后恢复

**Q：执行失败如何重试？**

A：任务执行失败后，系统会自动尝试重规划。如果自动重规划也失败：
- 在任务详情页点击"重试"
- 或取消当前任务，创建新任务重新执行

**Q：如何查看执行日志？**

A：在任务详情页的"执行时间线"标签页中，可以查看每一步的详细日志，包括工具调用、模型交互等信息。

### 10.4 安全相关

**Q：我的 API Key 安全吗？**

A：API Key 只存储在环境变量中，不入数据库，不写入任何日志。系统通过环境变量引用的方式使用 Key，确保 Key 值本身不会被泄露。

**Q：员工会不会删除我的文件？**

A：文件删除属于高危操作，必须经过你的审批才能执行。员工无法自行删除任何文件。此外，工作区隔离确保员工只能访问被授权的目录。

**Q：如何紧急停止所有任务？**

A：使用全局紧急开关（Kill Switch），一键停止所有正在执行的任务。这是紧急情况下的最后保障。

### 10.5 数据与备份

**Q：数据存储在哪里？**

A：AgentOS 的数据存储在本地 SQLite 数据库中，默认位于项目目录下。所有数据都在你的本机上，不会上传到任何外部服务器。

**Q：如何备份？**

A：
- **数据库备份**：复制 SQLite 数据库文件
- **组织配置备份**：使用组织配置导出功能（参见 3.6 节）
- **项目文件备份**：复制工作区目录

**Q：如何迁移到新机器？**

A：
- ① 在旧机器上导出组织配置
- ② 复制 SQLite 数据库文件和工作区目录
- ③ 在新机器上安装 AgentOS
- ④ 导入组织配置，放置数据库和工作区文件
- ⑤ 配置 `.env` 文件中的 API Key
